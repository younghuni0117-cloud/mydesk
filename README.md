# My Desk

정보와 자료, 배움의 기록을 모으는 개인 홈페이지입니다. 왼쪽 메뉴에서 홈, 정보·자료, 미로 탐험, 카트폴을 선택합니다. 각 콘텐츠는 독립된 HTML 페이지이며, 홈에서는 게임이 실행되지 않습니다. 모바일에서는 메뉴 버튼으로 사이드바를 여닫을 수 있습니다.

**홈페이지:** https://younghuni0117-cloud.github.io/mydesk/

## GitHub에서 수정하기

이 저장소의 `main` 브랜치에서 파일을 열고 연필(Edit) 버튼으로 수정한 뒤 Commit changes를 누르세요. GitHub Pages가 `main` 브랜치의 루트(`/`)에서 자동으로 다시 배포합니다. 진행 상황은 저장소 Actions 탭에서 확인할 수 있습니다.

자료를 추가하려면 `resources.html`에 내용을 넣고 필요에 따라 `index.html`에서 링크하세요. 새 페이지를 추가할 때 왼쪽 메뉴도 바꾸려면 각 HTML 파일의 `sidebar` 내 링크를 함께 수정합니다. 기존 공유 주소의 `#experiments`, `#cartpole`, `#how`는 새 게임 페이지로 연결됩니다.

## 로컬 실행

설치·빌드 없이 정적 서버로 실행합니다. 카트폴은 ES 모듈을 사용하므로 파일을 직접 열기보다 아래 명령을 사용하세요.

```sh
python3 -m http.server 8000
```

http://localhost:8000 에 접속합니다. Google Fonts를 불러올 수 없으면 기본 글꼴을 사용합니다.

## 강화학습 체험

미로는 탐험 비율과 속도를 조절하며 AI를 학습하거나 직접 이동할 수 있습니다. 학습 내용은 페이지를 벗어나면 초기화됩니다.

카트폴은 방향키와 터치로 직접 플레이하거나, 선택한 난이도의 AI를 학습한 뒤 보존 모델로 실행할 수 있습니다. 학습은 30세대 단위이며 실행은 자동으로 시작하지 않습니다. **학습 모델 실행**을 누르면 해당 난이도에서 가장 높은 고정 평가 평균을 얻은 모델의 가중치를 복사해 사용합니다. 실행 중 가중치는 바뀌지 않습니다.

### 난이도

| 난이도 | 물리·종료 조건 |
| --- | --- |
| 쉬움 | 긴 1단 막대, ±20° 허용 |
| 기본 | 기존 1단 막대, ±12° 허용 |
| 어려움 | 짧은 막대·높은 중력, ±10° 허용 |
| 2단 관절 | 두 막대를 직렬로 연결, 각 막대 ±20° 허용 |

모든 난이도에서 카트가 ±2.4m를 벗어나면 종료합니다. 0.02초마다 성공적으로 버틴 스텝에 +1을 받고, 1,000스텝(20초)이면 성공입니다. 2단 관절은 두 균일 막대의 연성 질량 행렬을 풀고 두 번의 중점 적분으로 움직임을 계산합니다. 위·아래 막대의 각도와 각속도는 독립 상태입니다.

### 학습·그래프·저장

CEM(Cross-Entropy Method)으로 1단은 4개 가중치, 2단은 6개 가중치를 학습합니다. 1단은 세대별 25개 후보·상위 6개, 2단은 49개 후보·상위 8개로 분포를 갱신합니다. 각 후보는 동일한 3개 학습 시작 조건을 시도합니다. 이후 각 세대 후보를 **난이도별 고정된 8개 시작 조건**으로 평가합니다. 학습은 후보 3개마다 브라우저에 제어를 넘겨 중지·난이도 전환이 가능하며, 취소된 세대는 모델에 반영하지 않습니다.

오른쪽 그래프의 회색 점선은 세대별 후보의 평가 평균 생존 시간, 파란 실선은 보존된 최고 모델의 평가 평균입니다. 20초 성공률도 이 8회 평가 기준이며, 매 실행의 무작위 시작 조건에서 똑같은 결과를 보장하지 않습니다. 그래프에는 최근 120개 기록을 표시합니다. 미리 훈련된 가중치나 정답 제어기는 사용하지 않습니다.

난이도별로 모델·학습 분포·그래프·내 최고 기록을 `mydesk.cartpole.v2.<difficulty>` localStorage에 나누어 저장합니다. 기존 v1 모델은 기본 난이도로 불러오고 새 평가 지표를 계산합니다. 초기화 버튼은 현재 난이도의 AI 학습만 지우고, 내 최고 기록과 다른 난이도의 모델은 유지합니다.

검증: `node --test tests/cartpole.test.mjs`

기존 Sites 사이트는 별도 배포이며, 이 저장소의 변경은 GitHub Pages 주소에 반영됩니다.

## 모바일·폴더블 게임 화면

두 게임은 기기 이름 대신 실제 가용 화면 크기로 배치합니다. 좁은 화면(너비 600px 미만)은 게임판 위·조작부 아래, 넓은 화면은 게임판과 조작부를 나란히 배치합니다. 회전한 외부 화면은 너비 540px 이상·높이 540px 미만일 때 가로 배치를 사용합니다. 게임 페이지에서는 내부 화면에서도 왼쪽 메뉴를 접어 게임 공간을 확보합니다.

화면 높이는 `visualViewport`와 동적 뷰포트에 맞추며, 접기·펼치기·회전·브라우저 주소창 크기 변화에 따라 다시 계산합니다. 도움말은 별도 대화상자에서 읽고, 지원 브라우저에서는 전체 화면 버튼을 사용할 수 있습니다. 게임 진행 화면에는 모드, 기록, 설정, 핵심 조작을 유지합니다. 도움말을 열면 진행·학습을 일시정지합니다.

가용 높이가 지나치게 작거나 브라우저를 확대하면 조작을 잘라내지 않도록 일반 스크롤 배치로 돌아갑니다. 실기기·브라우저 화면 검증은 별도로 필요합니다.
