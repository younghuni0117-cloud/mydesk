# My Desk

정보와 자료, 배움의 기록을 모으는 개인 홈페이지입니다. 왼쪽 메뉴에서 홈, 정보·자료, 미로 탐험, 카트폴, 2D 로봇을 선택합니다. 각 콘텐츠는 독립된 HTML 페이지이며, 홈에서는 게임이 실행되지 않습니다. 모바일에서는 메뉴 버튼으로 사이드바를 여닫을 수 있습니다.

**홈페이지:** https://younghuni0117-cloud.github.io/mydesk/

## 강화학습 체험

미로는 탐험 비율과 속도를 조절하며 AI를 학습하거나 직접 이동할 수 있습니다. 학습 내용은 페이지를 벗어나면 초기화됩니다.

카트폴은 방향키와 터치로 직접 플레이하거나, 선택한 난이도의 AI를 학습한 뒤 보존 모델로 실행할 수 있습니다. 학습 시도 횟수(1~10,000회)를 직접 입력하며, 게임 시작부터 실패 또는 20초 성공까지가 1회입니다. 입력한 횟수를 정확히 수행하고, 실행은 자동으로 시작하지 않습니다. **학습 모델 실행**을 누르면 해당 난이도에서 가장 높은 고정 평가 평균 누적 보상을 얻은 모델의 가중치를 복사해 사용합니다. 실행 중 가중치는 바뀌지 않습니다.

### 난이도

| 난이도 | 물리·종료 조건 |
| --- | --- |
| 쉬움 | 긴 1단 막대, ±20° 허용 |
| 기본 | 기존 1단 막대, ±12° 허용 |
| 어려움 | 짧은 막대·높은 중력, ±10° 허용 |
| 2단 관절 | 두 막대를 직렬로 연결, 각 막대 ±20° 허용 |

모든 난이도에서 카트가 ±2.4m를 벗어나면 종료합니다. 1,000스텝(20초)을 버티면 성공입니다. 실패한 시점에 시간과 점수를 확정한 뒤, 제어 입력 없이 막대가 바닥에 닿아 튕기고 가라앉는 모션을 보여줍니다. 이 종료 모션은 학습 시도·생존 시간·보상에 추가되지 않습니다. 모션을 일시정지하거나 이어 볼 수 있습니다. 2단 관절은 두 균일 막대의 연성 질량 행렬을 풀고 두 번의 중점 적분으로 움직임을 계산합니다. 위·아래 막대의 각도와 각속도는 독립 상태입니다.

### 학습·그래프·저장

CEM(Cross-Entropy Method)으로 1단은 4개 가중치, 2단은 6개 가중치를 학습합니다. 1단은 묶음별 25개 후보·상위 6개, 2단은 49개 후보·상위 8개로 분포를 갱신합니다. 각 후보는 동일한 3개 학습 시작 조건을 시도합니다. 이후 각 묶음 후보를 **난이도별 고정된 8개 시작 조건**으로 평가합니다. 학습은 게임 시도 3회마다 브라우저에 제어를 넘겨 중지·난이도 전환이 가능하며, 완료한 시도는 즉시 횟수에 포함됩니다. 요청 횟수 도달 또는 중지 시 현재까지의 후보를 별도로 평가해 최고 모델을 보존합니다. 미완료 후보·평가 순서·부분 점수를 저장해 다음 요청에서 정확히 이어갑니다.

오른쪽 그래프의 회색 점선은 평가 시점별 후보의 평균 누적 보상, 파란 실선은 보존된 최고 모델의 평균 누적 보상입니다. 20초 성공률도 이 8회 평가 기준이며, 매 실행의 무작위 시작 조건에서 똑같은 결과를 보장하지 않습니다. 가로축은 누적 학습 시도 횟수입니다. 성능 확인을 위한 별도 8회 평가는 입력한 학습 시도 수에 포함하지 않습니다. 그래프에는 최근 120개 평가 기록을 표시합니다. 미리 훈련된 가중치나 정답 제어기는 사용하지 않습니다.

난이도별로 모델·학습 분포·진행 중인 후보 평가·그래프·내 최고 기록을 `mydesk.cartpole.v3.<difficulty>` localStorage에 나누어 저장합니다. 기존 v1/v2 모델 가중치·누적 시도·내 최고 기록은 불러와 유지하고, 새 보상 규칙으로 다시 평가합니다. 과거 시간 그래프를 점수로 변환하지 않으며, 새 보상 그래프는 이관 시점의 누적 시도에서 시작합니다. 점수 단위가 다른 미완료 v2 후보 평가는 이관하지 않고, 원본 저장 키는 보존합니다. 초기화 버튼은 현재 난이도의 AI 학습만 지우고, 내 최고 기록과 다른 난이도의 모델은 유지합니다.

### 상벌점 규칙

- 유효한 스텝(0.02초)마다 기본 +1점
- 자세 감점: −0.2 × 각 막대의 `(각도/허용 각도)²` 평균
- 위치 감점: −0.05 × `(카트 위치/2.4)²`
- 제어 감점: −0.01 × `입력 힘²`
- 실패 순간 −100점, 20초 성공 시 +100점

그래프·후보 순위·보존 모델 선택에 같은 실제 누적 보상을 사용합니다. 보상 범위는 −100~+1,100점이며 0점 기준선을 표시합니다. 실패 후 충돌 모션은 보상에 영향을 주지 않습니다.

바닥 충돌은 질량 행렬을 통한 수직 충격량, 반발계수 0.38, 접선 마찰과 위치 보정을 적용합니다. 마찰이 수직 반발을 지우지 않도록 제약 공간에 투영합니다. 1단·2단 모두 전체 막대가 카메라에 들어오도록 시야를 조절합니다.

검증: `node --test tests/cartpole.test.mjs tests/cartpole-motion.test.mjs`

기존 Sites 사이트는 별도 배포이며, 이 저장소의 변경은 GitHub Pages 주소에 반영됩니다.

## 모바일·폴더블 게임 화면

두 게임은 기기 이름 대신 실제 가용 화면 크기로 배치합니다. 좁은 화면(너비 600px 미만)은 게임판 위·조작부 아래, 넓은 화면은 게임판과 조작부를 나란히 배치합니다. 회전한 외부 화면은 너비 540px 이상·높이 540px 미만일 때 가로 배치를 사용합니다. 게임 페이지에서는 내부 화면에서도 왼쪽 메뉴를 접어 게임 공간을 확보합니다.

화면 높이는 `visualViewport`와 동적 뷰포트에 맞추며, 접기·펼치기·회전·브라우저 주소창 크기 변화에 따라 다시 계산합니다. 도움말은 별도 대화상자에서 읽고, 지원 브라우저에서는 전체 화면 버튼을 사용할 수 있습니다. 게임 진행 화면에는 모드, 기록, 설정, 핵심 조작을 유지합니다. 도움말을 열면 진행·학습을 일시정지합니다.

가용 높이가 지나치게 작거나 브라우저를 확대하면 조작을 잘라내지 않도록 일반 스크롤 배치로 돌아갑니다. 실기기·브라우저 화면 검증은 별도로 필요합니다.

## 로봇 강화학습

몸 상태·목표 39개와 주변 지형 26개, 총 65개 입력 → tanh 은닉 12개 → 관절 토크 12개의 공통 신경망과 학습 가능한 센서-출력 연결(총 1,020개 가중치)을 사용합니다. 균형·일어서기·걷기·달리기·장애물 통과 모두 같은 통합 모델입니다. 새 통합 모델의 가중치는 0이고 미리 정한 보행·일어서기·PD/IK 제어는 없습니다. PPO의 새 탐색 정책은 숨은 특징만 무작위 초기화하고 출력층은 0으로 두므로 초기 결정론적 관절 토크도 0입니다.

### 보상 기준 v5

`robot-rewards.mjs`가 실제 보상과 도움말을 함께 정의합니다. 이전에는 누워 정지한 로봇에도 몸을 지탱하는 접촉 충격량으로 초당 약 −4.26점이 붙었습니다. 이제 `pre-solve`에서 새로 발생한 접촉의 접근 속도를 확인하고, 0.6m/s 초과 충돌의 초과 운동에너지에만 0.06점/J를 감점합니다. 정지한 지지 접촉의 충격 벌점은 0입니다. 넘어짐·기울기·에너지 비용은 별도 유지합니다.

속도 보상은 높이·몸통 방향·발 접촉으로 정하는 연속적인 자세 품질(0~1)을 곱합니다. 낮은 자세로 정지하면서 일어서기의 속도 보상만 받는 유인을 줄입니다. 일어서기는 지면 기준 골반 높이 증가 6점/m, 상체 자세 품질 증가 2점/단위, 0.8초 넘게 서 있기 성공 +8점입니다. 되돌아가는 움직임은 같은 비율로 감점합니다. 이는 결과에 대한 보상이며 관절 동작을 지정하지 않습니다. 낮은 자세 명령에는 0.62m 목표 높이에 맞춰 품질·서 있기 판정을 조정합니다.

### 개선 CEM과 PPO

새 사용자의 기본값은 PPO이며 기존에 저장한 CEM/PPO 선택은 유지합니다. 개선 CEM도 선택할 수 있습니다. 균형은 32회마다 16개 정책을 각각 좌우 두 초기 기울기에서 비교합니다. 현재 탐색 평균과 통합 모델을 기준으로 포함하고, 나머지는 일곱 쌍의 반대 방향 변화입니다. 각 정책의 평균·최저 실제 유지 시간을 함께 비교하고 기준 통합 모델을 제외한 상위 여덟 정책으로 분포를 갱신합니다. 다른 과제는 같은 시작 조건의 32개 정책을 비교합니다. 탐색 분포·반복 실험의 난수 시드를 저장합니다.

상세 옵션에서 PPO와 CEM을 선택할 수 있습니다. `robot-ppo.mjs`는 기존 actor와 39→12→1 가치 함수, 대각 Gaussian 탐색, GAE(γ=.995, λ=.97), clipped PPO(clip=.2), Adam, gradient clipping과 KL 조기 중단을 구현합니다. 20Hz 정책 결정의 행동·로그 확률·가치·보상을 기록하고 8개 시도 단위로 확인하고 경험 256개 이상일 때 4 epoch/64 minibatch로 학습합니다(요청 종료 시 최소 64개). 경험이 부족하면 정책을 바꾸지 않고 다음 묶음까지 보관합니다. 새 PPO의 숨은 특징은 센서별 크기에 맞춰 무작위 초기화하고 출력층은 0으로 두며 초기 탐색 표준편차는 exp(−2.3), 최소 exp(−2.8)입니다. v42는 구조 변경으로 이전 모델을 초기화합니다. 정책 lr=.0003, 가치 lr=.001, entropy=.01입니다. CEM은 32회마다, PPO는 대체로 두 번의 정책 갱신마다 선택 운동의 네 조건으로 후보를 선별하고, 36회 또는 요청 종료 시 가장 좋은 선별 후보의 나머지 운동·명령을 검증합니다. 실제 통합 모델 채택 전에는 다섯 운동 각 네 조건과 네 명령 조건을 모두 확인합니다. 사전 선별 결과는 재사용합니다. 따라서 통합 모델 갱신은 이전보다 드물 수 있습니다. 실제 물리 시도만 횟수로 세며(기본 8~12초, 균형 학습은 실패 시 조기 종료 가능) 최적화 epoch나 검증은 합산하지 않습니다. actor·critic·Adam·미처리 경험을 저장합니다. PPO를 쓰면 항상 더 잘 학습한다는 보장은 없습니다.

학습 중인 탐색 정책과 통합 모델을 구분합니다. 미숙한 운동의 원시 점수 변화는 허용하지만 이전에 통과한 네 검증 조건을 잃은 후보는 통합 모델로 채택하지 않습니다. 통과율 50% 이상인 능력은 평균 보상 5%(최소 2점)의 허용 폭도 검사합니다. 후보가 기존 조건을 잃으면 남은 검증을 생략하고, 미평가 후보 점선은 비워 둡니다. 조기 이탈로 끝난 검증의 운동 성능은 0으로 취급하고, 이전에 전체 시간을 완료한 조건을 조기 종료로 대체하지 않습니다. 통합 모델 갱신은 선택 운동의 통과율·실제 운동 성능·보상 순으로 개선을 비교하고, 기존에 통과한 조건·숙련 능력을 보존할 때 이루어집니다. 전체 보상 합산만으로 선택 운동의 성능 저하를 허용하지 않습니다. 선택 운동의 실제 성능은 서 있는 비율·자세 품질·최장 유지·외력 후 서 있는 시간, 일어서기 성공·진행 거리·장애물 통과를 과제에 맞게 반영합니다.

### 단계 학습·병렬 계산·관찰

균형은 항상 제자리 유지를 학습합니다. 단계별 학습을 켜면 외력 없는 2초·4초 유지부터 시작하고, 외력 없는 고정 검증의 최장 유지가 각각 1.5초·3.5초를 넘으면 다음 단계로 갑니다. 8초 단계에서 자동 밀기를 적용합니다. 단계를 꺼두면 처음부터 8초·설정한 밀기를 사용합니다. 다른 운동은 기본 목표를 먼저 연습하고 검증 통과율 50% 이후 명령 변경을 섞습니다. 외력은 사용자가 정한 최소~최대 범위 안에서 상한을 낮게 시작하고, 검증 통과율에 따라 상한과 초기 흔들림을 늘립니다. 각 묶음 안에서는 동일한 조건을 고정합니다. 검증은 단계와 무관하게 같은 정지·2/4/6 N·s 외력 조건을 씁니다. 자동 밀기는 적용 단계에서 체크 시 시도당 무작위 방향·시점에 한 번 예약하며 체크를 끄면 0번입니다. 균형 시도가 밀기 시점 전에 조기 종료되면 실행되지 않을 수 있습니다. 사용자의 최소 세기보다 약하게 만들지 않습니다.

보고 코어가 4개 이상이면 기존 학습 작업자 옆에 물리 작업자 하나를 추가하여 최대 두 후보·검증 조건을 동시에 계산합니다. 결과·시드·모델 반영 순서는 유지하며 CEM 32회/PPO 8회 묶음 경계를 넘지 않습니다. 지원 불가·실패 시 같은 시도를 순차 계산합니다. 중지 후 아직 반영하지 않은 추가 결과는 버립니다. 같은 지형에서 재학습·과제 변경은 준비된 작업자를 재사용합니다.

학습 중 최근 모델의 실제 시도 장면을 보간 재생해 화면에서 같은 물리를 중복 계산하지 않습니다. 직접 밀기·통합 모델 실행·학습 종료 후 관찰은 실시간입니다. 왼쪽 드래그는 밀기, 오른쪽은 시점 이동, 휠·두 손가락은 확대·이동입니다. 버튼 순서는 학습 시작 → 중간 관찰 → 통합 모델 실행입니다. 통합 실행 중 명령 변경은 몸·속도·관찰시간을 초기화하지 않습니다.

### 그래프와 기록 보존

그래프의 가로축은 선택한 운동 능력의 실제 시도 횟수이며 다른 능력의 횟수는 합산하지 않습니다. 실선은 통합 모델, 점선은 실제 평가한 후보의 평균 보상입니다. 상세 옵션에서 전체(0~현재), 최근 500/1,000/2,000/5,000/10,000회 또는 직접 입력을 선택합니다. 표시 범위는 데이터를 삭제하지 않습니다. 보상 버전과 지형이 다른 점수는 섞지 않으며, 업데이트 전 원본 그래프도 별도로 볼 수 있습니다. 이전 버전에서 이미 압축·생략된 점을 만들어 내지는 않습니다.

로그인 없이 한 개의 공개된 공용 모델을 PC·모바일이 함께 사용합니다. 최신 가중치·학습 횟수·그래프·CEM/PPO 학습 상태를 받아오며 마지막 저장 결과가 공용 모델이 됩니다. 학습 중에는 최대 30초 간격, 학습 완료·중지 때에는 즉시 저장합니다. 학습하지 않을 때에는 15초마다 변경을 확인합니다. 학습 시작과 페이지 복귀 때도 최신 결과를 확인합니다.

기존 Supabase 서버를 재사용하고 방문자 가입·로그인·토큰 입력은 없습니다. 공개 client key와 단일 행 RLS만 사용합니다. 서버가 비었으면 기존 기록이 있는 기기에서 처음 등록하며, 학습 없는 새 기기는 빈 모델을 올리지 않습니다. 이후 누구나 낮은 횟수·다른 모델로도 덮어쓸 수 있습니다. 기기별 결과를 자동 병합하지 않습니다. 현재 상태 한 개만 로컬 캐시하고 연결 실패 시 자동 재시도하며, 새 백업·복원 기록을 만들지 않습니다. 초기화는 확인 후 공용 모델에 적용합니다. 상세 내용과 스키마는 `sync/README.md`, `sync/public-model.sql`을 참고하세요.

### 물리·외형·지형

13개 강체·12개 관절·총 질량 19.9kg, 관절 제한·모터 토크/속도 한계·마찰·중력·충돌을 계산합니다. 허리의 수동 내부 강성 55 N·m/rad·감쇠 9 N·m·s/rad는 유지합니다. 정책은 걷기·달리기 10Hz/그 외 20Hz, 물리는 120~720Hz 하위 스텝, 화면은 주사율에 맞춰 보간합니다. 탐험가·깡통·스타워즈형·등산객·김도윤·임선아 외형은 같은 물리와 모델을 씁니다. 김도윤·임선아는 상C 작가의 [공식 작품](https://comic.naver.com/webtoon/list?titleId=836848)을 참고해 직접 그린 팬 스킨입니다.

지형은 초원 → 사막 → 돌길 → 언덕 → 계단 → 공사장 → 빙판 → 동굴 탐험입니다. 평활한 초원·마찰 0의 빙판, 약 48도 곡면 언덕, 물웅덩이·둥근 돌, 휴식 평지가 있는 계단, 공사장 사물, 높낮이 5배와 최소 3.3m 여유의 동굴을 유지합니다. 배경 제작은 `assets/README.md`를 참고하세요. 폴드 외부 화면은 실행 버튼을 고정하고 내부 가로 화면은 접힌 메뉴 상태에서 한 화면에 맞춥니다.

### 검증과 비교

`node --test tests/*.test.mjs`로 현재 로봇 및 다른 기능의 회귀 검사를 실행합니다. `tests/robot-v6.test.mjs`는 실제 관절 제거·질량 보존, 65입력/12출력, PPO 수치 미분, 정지/이동 보상, 균등 센서, 상벌점 총합·팝업, CEM/PPO 갱신, 구형 모델 거부를 검사합니다. `NODE_PATH=/opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules node scripts/verify-robot-v6.cjs`는 Chromium 데스크톱/모바일과 실제 작업자 초기화를 검사하며 공유 API는 격리합니다. v5 전용 이전 검사들은 `tests/legacy-robot-v5`와 `scripts/legacy-robot-v5`에 보관했습니다. 실제 Fold/Edge 기기나 장기 학습 수렴을 검증한 것은 아닙니다.

### v23 속도·보상 보완

지형의 바닥 조각과 동굴 천장은 각각 하나의 고정 물체에 동일한 충돌 도형을 연결합니다. 물리 시간 간격·반복 횟수·마찰·관절은 유지하며 `groupStatic:false`로 기존 구조와 비교할 수 있습니다. 학습 메시지에서는 지형·도형을 제외하고 관찰 메시지에서는 PPO 경험 배열을 제외합니다. PPO 역전파는 같은 샘플의 전방 계산과 Float64 작업 공간을 재사용합니다.

이동 보상은 자세에 관계없이 같은 부호의 위치 잠재량 차이를 사용합니다. 왕복 이동의 진행 점수는 상쇄되며, 전진 점수는 목표 속도×예정 시간의 범위로 제한합니다. 목표 속도 절댓값을 0.05m/s 넘은 초과 속도 e에 초당 −(8e+2e²), 정규화 토크 제곱 평균에 초당 −0.05, 행동 변화 제곱 평균에 −0.02를 적용합니다. 조기 영역 이탈·수치 오류는 총 보상을 −20−8×예정 시간 이하로 낮추고 검증 실패로 판정합니다. 미리 만든 관절 동작은 추가하지 않습니다.

저장 키 `mydesk.robot.v5`는 유지합니다. 현재 물리 버전은 4, 정책 형식은 `direct-torque-sensor-mlp-v3`입니다. v2 보상 모델은 원본 바이트를 `mydesk.robot.archive.reward2` 및 별도 IndexedDB 기록으로 보관하고, 가중치·actor/critic·Adam·횟수·기록을 유지합니다. 기존 보상으로 모은 미처리 경험과 CEM 후보 점수만 새 학습에서 분리합니다. 원본에는 그대로 남습니다. 과거 보상 그래프는 상세 옵션에서 선택할 수 있습니다. 새 보상 수치를 옛 수치와 직접 비교하지 마세요.

검증: 기존 11개 로봇 테스트 파일과 v23 보상·지형 동일성·검증 일정·이전 버전 저장 테스트를 통과했습니다. Chromium에서 실제 PPO 100회, 병렬 학습/중지/복구, IndexedDB 복원과 390×760/720×480 배치를 확인했습니다. Edge/실제 Fold 기기 측정은 아닙니다. 동일 환경의 10초 물리 시도 3회 중앙값(`scripts/benchmark-robot-static.mjs`, `benchmarks/robot-v23-physics.json`)은 언덕 535→361ms, 동굴 1,162→672ms였습니다. 고정 지형 묶음만 비교한 수치이며 전체 학습 시간이나 모든 기기의 동일한 단축률을 뜻하지 않습니다. PPO 전방 계산 재사용은 같은 경험 배열에서 이전 구현과 actor·critic·Adam·통계가 정확히 일치했습니다.


### v29 학습 정체·표시 보완 (이전 변경 기록)

CEM의 5개 반대 방향 쌍은 하나의 출력 bias, 한 출력의 가중치, 한 은닉 특징, 부분 가중치, 작은 전체 변화로 나누어 탐색합니다. 통합 모델 개선 없이 72회가 지나면 현재 탐색을 보관하고 탐색 폭을 0.08/0.14/0.22로 순환하며 재조정합니다. 세 번째 재탐색은 0 가중치 중심에서도 찾고, 기존 통합 모델은 항상 기준 후보로 남깁니다. 미리 정한 움직임은 없습니다.

PPO는 균형 실패 후의 긴 데이터가 대부분을 차지하지 않도록 8회 중 7회를 넘어짐 0.35초 지속 시 종료하고, 한 번은 전체 시간을 연습합니다. CEM 균형 학습도 같은 조기 종료를 사용합니다. 실패하면 남은 예정 시간에 초당 −6점의 비용을 더해 빨리 끝내서 벌점을 피하는 유인을 줄입니다. 일어서기와 관찰·검증은 전체 시간을 계속합니다. PPO가 128회 이상 통합 모델을 개선하지 못하고 평가한 탐색 정책도 뒤처지면, 이전 actor·Adam·경험을 보관하고 통합 모델에서 작은 탐색 폭으로 다시 시작합니다. 가치 함수·가치 Adam·누적 정책 갱신 횟수는 유지합니다. CEM/PPO 교대 때도 탐색 정책을 비교하고 뒤처진 정책만 재동기화합니다.

자세 품질 q는 발 지지, 골반 높이, 몸통 방향, 몸통의 지면 접촉을 함께 평가합니다. 균형은 초당 8q²−4(1−q), 다른 운동은 4q²−4(1−q)를 적용합니다. 낮은 자세 명령은 높이 기준을 따로 낮춥니다. 몸통만 세운 낮은 자세의 벌점 감소와 실제 서 있는 운동을 구분합니다. 그래프 아래에는 고정 검증에서 서 있는 시간과 최장 유지 시간을 표시합니다. 별도 두 조건의 결과는 상세 옵션에서 확인하며 모델 선택에 쓰지 않습니다.

보상 v2/v3의 원본은 각각 `mydesk.robot.archive.reward2/reward3`와 IndexedDB에 보관합니다. 복구 후보 중 가장 최신의 유효한 원본을 선택합니다. 정책 형식·모델 버전 5·저장 키는 유지하고 기존 가중치·탐색 분포·actor/critic/Adam·횟수·옛 그래프를 옮깁니다. 새 점수로 쓸 수 없는 미처리 경험·후보 점수는 원본에 보존하고 새 학습에서 분리합니다. 보상 변경 이전과 이후 점수의 크기를 직접 비교하지 않습니다.

로봇 좌측 상단 모델 설명을 숨기고 프레임마다 쓰던 문구 갱신도 제거했습니다. 진행 게이지 숫자는 최대 초당 한 번, 예상 남은 시간은 최대 5초에 한 번(분 단위) 표시합니다. 완료·중지는 정확한 최종 횟수를 즉시 표시합니다. 상세 옵션의 카메라 설정과 오른쪽 패널 독립 스크롤은 유지합니다.

검증 결과는 `benchmarks/robot-v29-learning.json`에 기록했습니다. 초원에서 seed 42/73, 각 240회로 시작한 단기 진단의 고정 검증 평균 서 있는 시간은 CEM 0.85~0.86초, PPO 0.46~0.49초(초기 약 0.39초)였고, 별도 미사용 시드에서도 각각 약 0.80~0.87초와 0.45~0.46초였습니다. 네 실행 모두 검증 통과율은 0%이므로 균형 완성·장기 수렴·알고리즘 우열을 증명하지 않습니다. 조기 종료 때문에 이전 버전의 같은 시도 수와 물리 경험량이 다르며, 보상 v3/v4 점수는 직접 비교하지 않습니다. `scripts/diagnose-robot-learning.mjs`로 현재 구현을 재현할 수 있습니다.

기존 13개 로봇 테스트 파일과 추가 데이터 이전·성능 채택·PPO 경험 누적·CEM/PPO 정체 복귀 검사를 실행했습니다. Chromium에서 v3 실제 진단 모델의 원본 바이트·가중치·횟수·탐색 분포를 보존하고 CEM 100회를 추가했으며, v4 구형 파일의 12,000회·가중치를 유지하고 PPO 100회를 추가했습니다. IndexedDB 복구·재접속·파일 왕복·병렬 중지/복구·기록 재생과 실시간 밀기, 390×760/720×480/650×900 배치를 확인했습니다. CEM 100회 진행 중 게이지 문구는 11번, 상태 문구는 4번 갱신되었습니다. 실제 Fold 기기나 Edge 실행 결과를 뜻하지 않습니다.

PPO 240회 모델을 이어 304회까지 실행해 정체 복귀가 실제로 한 번 작동하고, 누적 정책 갱신 38회·기록 형식·학습 횟수가 유지되는 것도 확인했습니다.

### v30 균형 학습 집중 개선

완전히 펴진 무릎에서 모터 힘을 0으로 낮추던 토크 감쇠를 제거했습니다. 해부학적 관절 각도 제한과 힘·속도 한계는 유지합니다. 관절이 펴졌어도 힘을 낼 수 있으며 추가 지지력·자세 제어는 없습니다.

기존 MLP의 784개 가중치를 순서와 값 그대로 유지하고, 관절별 자기 각도·속도·몸통 기울기·몸통 각속도·골반 속도·목표 속도에서 출력으로 이어지는 96개 학습 계수를 덧붙입니다. 새 계수는 모두 0입니다. 반응 방향·관절 목표·기본 동작을 미리 정하지 않으며 CEM/PPO가 보상으로 계수를 학습합니다. 초기 통합 모델과 새 탐색 정책의 결정론적 관절 출력은 모두 0입니다.

균형의 서 있기 보상을 초당 +10점, 기준 미달을 −2점으로 조정하고 중복 고정 넘어짐 벌점을 제거했습니다. 자세 품질·지지·드리프트·충격·힘 비용은 유지합니다. CEM 선발은 실제 서 있는 초수와 최장 유지 시간을 중심으로 합니다. 통합 모델은 검증 통과율, 최악 조건의 실제 서 있는 시간, 평균 서 있는 시간 순으로 비교하여 낮게 웅크려 보상만 개선한 후보를 우선 채택하지 않습니다. 다른 운동의 기존 성공 조건도 보호합니다.

기초 균형에서 강한 밀기를 지연하는 2→4→8초 학습과 좌우 기울기 비교를 도입했습니다. 균형 훈련은 시작 0.2초 이후 서 있기 기준에서 0.2초 넘게 벗어나면 조기 종료하고 남은 시간의 실패 비용을 적용합니다. PPO 8회 중 한 번, 일어서기·관찰·검증은 예정 시간까지 계속합니다. CEM 정체 복귀는 4,096회, PPO는 2,048회 이후로 늦춰 진행 중인 탐색을 너무 자주 지우지 않습니다. PPO는 시간 제한 종료에서 가치 함수를 부트스트랩하고, 다음 시도의 보상이 이전 시도의 GAE에 섞이지 않게 분리했습니다.

이전 보상 v4 원본을 `mydesk.robot.archive.reward4`와 IndexedDB에 그대로 보관합니다. 가중치·탐색 분포·actor/critic·Adam·횟수·과거 그래프를 이전하며 새 연결·Adam 모멘트만 0으로 추가합니다. 새 물리/보상에서 유효하지 않은 미처리 경험·후보 점수는 원본에 보존하고 새 학습에서 분리합니다. 물리·보상 변경으로 같은 가중치의 동작·점수는 달라질 수 있습니다. 새 평가와 옛 그래프는 구분합니다.

학습 완료 문구는 최종 로컬·IndexedDB 저장 작업을 기다린 뒤 표시합니다. 완료 직후 읽었을 때 마지막 두 시도가 아직 저장 큐에 남아 있던 문제를 브라우저 CEM 검사로 재현하고 수정했습니다.

재현 결과는 `benchmarks/robot-v30-balance.json`에 기록했습니다. 초원·4,096회·seed 42 CEM의 고정 8초 검증 평균 서 있는 시간은 v29 1.03초에서 v30 1.74초로 늘었습니다. v30 CEM seed 17은 1.57초, PPO seed 42는 1.75초였습니다. 선택에 사용하지 않은 네 개의 외력 없는 시드에서는 각각 기존 CEM 0.99초, 새 CEM 1.62/1.64초, 새 PPO 1.57초였습니다. 고정 검증 통과율은 모두 0%이므로 균형 완성이나 100,000회 수렴을 입증하지 않습니다. 물리·보상과 경험 길이가 달라 평균 보상·실행 시간을 직접 비교하지 않습니다. `node scripts/diagnose-robot-balance.mjs 4096 42 cem /tmp/balance.json`으로 새 구현을 재현할 수 있습니다.

총 16개 테스트 파일을 검사했고, 실제 서 있는 시간 우선 채택으로 바뀐 기준에 맞춰 기존 합산 보상 단조 증가 검사를 수정한 뒤 해당 검사를 다시 통과했습니다. CEM 32회 전체 묶음의 순차/병렬 동등성, 직립 무릎의 실제 토크, 시간 제한 GAE, 100,000회 구형 파라미터 이전, 원본 보관·백업 승격도 확인했습니다. Chromium에서 구형 CEM/PPO 데이터를 보존하며 각각 100회를 추가하고 완료 직후 횟수·재접속·IndexedDB 복구를 확인했습니다. 390×760/720×480/650×900 화면과 오른쪽 독립 스크롤·중지/재개도 검사했습니다. 실제 Fold/Edge 기기 검사를 뜻하지 않습니다.

### v31 로그인 없는 공용 모델 자동 공유

`robot-shared-storage.mjs`가 공용 모델 읽기·마지막 저장 결과 우선·서버 변경 감지·미전송 재시도를 처리합니다. 홈페이지의 로그인·이메일·파일 이동·백업/복원 조작 없이 동작합니다. 학습 중에는 현재 기기의 정책을 유지하고, 완료 시 자동 저장합니다. 첫 등록은 기존 학습을 우선해 빈 신규 방문이 학습 기록을 덮어쓰지 않도록 했습니다. 초기화는 모든 기기에 반영됩니다. 물리·정책·보상·학습 알고리즘은 v30과 같습니다. 위의 v30 이전 백업·복원 설명은 과거 변경 기록입니다.

공용 저장 단위 검사와 실제 작업자 UI 검사, 격리된 Chromium 두 기기의 양방향 100회 학습·가중치/옵티마이저/그래프 공유·오프라인 재전송·공용 초기화·390×760/720×480/650×900 배치를 확인했습니다. 실제 Supabase 익명 역할의 INSERT/UPDATE와 변경 번호 증가는 롤백하는 트랜잭션에서 검사했고, 브라우저의 실제 공개 API 연결도 확인했습니다. 배포 전 공용 행은 비워 기존 학습 기기의 첫 등록을 기다립니다.

## 가족 달력

메인 메뉴와 홈 카드의 `calendar.html`에서 월·주·일 달력과 일정 목록을 볼 수 있습니다. 제목, 시작/종료 날짜, 종일/시간, 공통·영훈·서정·하경·하윤 라디오 선택, 메모와 여러 날 일정을 지원합니다. 기존 일정의 이름·장소는 입력칸 제거 후에도 저장 시 보존합니다. 날짜의 빈 공간이나 ‘일정 만들기’로 등록하고 기존 일정을 누르면 수정·확인 후 삭제할 수 있습니다. 모든 날짜·시간은 서울 기준으로 해석합니다.

로그인 없이 공유 링크로 가족 달력을 함께 사용합니다. 연결 정보가 없는 새 기기는 기존 가족 달력의 공유 링크로 연결하거나 별도 새 달력 만들기를 직접 선택합니다. 별도 달력을 만들면 브라우저가 무작위 UUID 가족 키를 만들며, `#family=…` 링크를 가족에게 보내면 같은 달력에 입장합니다. 기기별로 마지막 사용한 가족 키를 기억하므로 이후 메인 메뉴에서 같은 달력을 엽니다. 가족 링크를 아직 받지 않은 새 기기의 기본 달력은 별도 공간입니다. 링크 소지자는 해당 달력을 조회·등록·수정·삭제할 수 있습니다. 링크 키는 웹사이트 코드에 고정하거나 서버에 URL 쿼리로 보내지 않고 fragment와 요청 헤더로 전달합니다.

기존 Supabase 프로젝트의 `family_calendar_events`를 사용하고, RLS는 요청 `x-client-info: mydesk-calendar/<가족 키>`와 행의 `calendar_id`가 일치할 때만 읽기·쓰기를 허용합니다. 링크가 없거나 다른 가족 키이면 일정이 보이지 않으며, 다른 가족으로 행을 옮기는 수정도 차단합니다. 공개 client key만 사용합니다. 로봇 모델의 공유 설정은 바꾸지 않았습니다. SQL은 `sync/family-calendar.sql`입니다. 일정은 20초마다, 화면 복귀·새로고침 때 서버에서 갱신합니다. 오프라인 저장을 성공으로 표시하지 않고 입력창과 오류 안내를 유지합니다.

검증: `node --test tests/calendar.test.mjs`는 서울 시간, 윤년·월/연도 경계, 여러 날 일정, 시간 역전, 익명 헤더, 조회 범위·페이지 나누기, 같은 UUID 재시도를 확인합니다. `node scripts/verify-family-calendar.cjs`는 새 무작위 테스트 가족 공간에서 실제 서버의 PC↔모바일 공유, 수정, 날짜/시간·종일 일정, 목록 보기, 달력 주소 유지, 재접속, 확인 후 삭제와 1440×1000/390×844/720×480 화면을 검사합니다. 테스트가 만든 UUID만 정리하며 기존 가족 일정·로봇 데이터에 접근하지 않습니다. 별도의 롤백 트랜잭션으로 가족 간 접근 차단·쓰기 제한·링크 없는 조회 차단을 확인했습니다. 실제 Fold/Edge 장치 검사는 아닙니다.

### 달력 v3: 간결한 배치·가족 이름·공휴일

상단 제목 영역을 제거하고 월/일정 목록·공유 링크·일정 만들기를 같은 버튼 줄에 배치했습니다. 일정 종류의 표시 이름은 공통·영훈·서정·하경·하윤입니다. 기존 저장 값 `family/personal/school/medical/other`는 같은 순서로 유지하므로 예전 일정·참여자·날짜·메모와 가족 공유 키가 바뀌지 않습니다. 서버 스키마나 실제 일정을 변환·초기화하지 않습니다.

공휴일·대체공휴일은 빨간 날짜와 이름으로, 미니 달력·선택 날짜·일정 목록에도 표시합니다. 가족 일정과 별도로 읽기 전용 표시하므로 DB에 중복 저장하거나 업데이트 때 사용자 일정을 덮어쓰지 않습니다. 2018~2027년 발표 자료를 포함하며, 출처·라이선스·확인일은 `data/README.md`에 기록했습니다. 미발표 연도의 휴일을 임의로 생성하지 않습니다.

### 블로그 비밀번호 설정·변경
관리 연결된 브라우저의 `글 관리 설정 → 비밀번호 설정`에서 새 비밀번호와 확인을 입력합니다. 다른 브라우저에서는 `글 관리 → 관리 비밀번호 → 연결`로 관리합니다. 최초 설정 전에는 기존 관리 링크/키가 유지되며, 최초 설정 후에는 이전 키가 해제됩니다. 이후 같은 화면의 `비밀번호 변경`으로 바꿉니다. 변경할 때 다른 기기의 모든 기존 세션을 무효화하고 현재 기기에 새 세션을 발급합니다. 연결은 최대 30일 유지하며 해당 브라우저에서 연결을 해제할 수도 있습니다.
`sync/blog-password.sql`은 기존 관리 키 해시를 기존 RLS 정책에서 옮기는 서버 스키마입니다. 비밀번호는 비공개 스키마에 bcrypt(cost 12) 해시로만 저장하고 브라우저에는 무작위 세션 토큰만 저장합니다. 토큰도 서버에는 SHA-256 해시로 저장합니다. 비밀번호는 8자 이상/UTF-8 72바이트 이내이며 잘못된 로그인 5회 뒤에는 30초간 재시도를 제한합니다. 공개 RPC는 SECURITY INVOKER이며, 비공개 함수의 실제 권한 검사는 기존 키 또는 활성 세션을 기준으로 합니다. 비공개 테이블은 직접 접근을 차단하고 글의 공개 읽기 정책은 유지합니다. 글, 달력, 로봇 모델 데이터를 변경하거나 초기화하지 않습니다.

### 앞으로 걷기 평가 개선 (robot37 / reward v7)
걷기는 목표 방향 진행을 1m당 최대 +8점, 목표 속도 일치를 초당 최대 +4점으로 평가합니다. 양의 진행과 속도 보상에 발 지지·골반 높이·몸통 방향 품질을 곱하고, 쓰러짐·회복 중이거나 머리/몸통/골반이 지면에 닿아 있으면 이 가점은 주지 않습니다. 역방향 진행은 전액 감점해 지지 품질을 바꾸며 같은 구간을 왕복하는 방식으로 점수를 벌지 못하게 합니다. 이동 목표 중 단순 서 있기 보상은 초당 +0.5점, 자세 품질은 q²−4(1−q)점으로 조정하고 정지 명령의 서 있기·도착 보상은 유지합니다. 넘어짐 −30점, 쓰러짐/회복 중 초당 −8점이며 재기립 보상 +8점은 유지합니다. 회복 후 걷는 경험을 계속 수집하며 동작·관절 제어를 미리 지정하지 않습니다.

### 관절 제거·이동 탐색·상벌점 게이지 (robot42)

손목과 발앞꿈치 회전 관절을 실제 제거하고 손/발끝 형상을 팔뚝/발 강체에 합쳤습니다. 질량 19.9kg과 캐릭터 외형은 유지하며, 네 관절에 쓰던 입력·출력도 제거했습니다. 모델 v6/물리 v5/보상 v9와 1,020개 가중치를 사용하며 이전 로봇 데이터는 초기화합니다. 달력·블로그 저장 데이터에는 손대지 않습니다. 서버 제약도 새 구조만 받아 구형 탭이 이전 모델을 덮어쓰지 못하게 합니다.

걷기와 달리기의 이동 목표에서는 서 있기 보상을 크게 줄이고 목표 속도 40% 미만에 정체 벌점을 줍니다. 전진 보상은 지지·자세 품질을 반영하며 뒤로 밀리는 이동은 감점합니다. 명시적 제자리 유지·목표 도착은 정체 벌점에서 제외합니다. PPO 탐색 폭과 미래 보상 반영을 늘리고 이동 행동을 0.1초 유지하며, CEM도 일부 시도에서 여러 관절을 함께 탐색합니다. 넘어짐에 대한 벌점은 유지하고 후보 비교에 실제 이동 성능을 반영합니다. 정해진 보행 동작은 추가하지 않았으며, 개선 여부는 추가 학습으로 확인해야 합니다.

센서는 좌우 각각 17개를 -92~85도에 동일 각도 간격으로 배치합니다. 지형 접점의 실제 공간 간격은 거리에 따라 다릅니다. 숫자는 해당 신체 부위의 실루엣 바로 주변에 배치하고 몸·옷·손발과의 겹침을 피합니다. 화면 하단의 왼쪽 초록/오른쪽 빨강 막대는 현재 시도의 보상 총합과 벌점 절댓값 총합 비율입니다. 서로 상쇄한 순보상이 아니며 작은 보상 항목도 합산합니다.

### 짧은 학습의 결과 표시·게이지·이동 깃발 (robot43)

보상 정보 → 같은 길이의 상벌점/학습 진행 막대 → 학습 정보 → 관찰 시간·이동 거리·평균 속도·회복/통과 순으로 정리했습니다. 각 시도에서 출발점으로부터 가장 멀리 간 위치에 작은 깃발을 표시합니다. 앞뒤 이동을 모두 고려하며, 되돌아와도 최대 위치를 유지하고 새 시도에서는 초기화합니다. 학습 모델과 기존 공유 데이터 형식은 유지합니다.

`tests/robot-preview43.test.mjs`는 실제 1초 미만 균형 실패의 마지막 벌점 재생, 첫 집계, 되돌아온 뒤에도 유지되는 최대 이동 위치를 검사합니다. `scripts/verify-robot-v6.cjs`는 API를 격리한 Chromium에서 짧은 장면의 종료 벌점, 새 장면 대기, 깃발, 390×844/768×1000/1080×720 화면의 막대 길이·간격·정보 순서를 검사합니다.

### 균형 관찰 종료 정지 제거 (robot44)

균형잡기의 마지막 자세를 0.8초 붙잡아 두는 표시를 제거했습니다. 장면이 끝나면 대기 중인 다음 장면으로 넘어가거나 즉시 반복합니다. 마지막 상벌점 숫자는 움직이는 장면 위에서 기존 수명 동안만 남습니다. 다른 운동의 재생·게이지·깃발·학습 데이터·보상 기준은 유지합니다. 짧은 실제 균형 실패에서 종료 이후 프레임이 다시 움직이면서 벌점도 표시되는 것을 회귀 검사합니다.

### 과정 로그·시간 표기·누적 이동 기록 (robot45)

화면의 실제 시도 시간은 ‘경과 시간’, 상세 옵션의 관찰 제한은 ‘모델 실행 시간’으로 구분합니다. 수치 세 항목을 한 줄로 배치하고 회복/통과와 예상 남은 시간의 별도 상태 줄을 제거합니다. 상태·학습 표본 결과·정책/검증 단계·통합 모델 채택·실제 화면의 밀기/넘어짐/회복은 왼쪽 과정 로그에 표시합니다. 최대 160줄, 얇은 스크롤바, 위로 읽을 때 자동 따라가기 중단을 적용합니다. 화면 재생과 실제 학습 계산을 명시적으로 구분합니다. 밀기 수치는 실제 물리 이벤트의 충격량(N·s)·방향·부위를 사용합니다.

상벌점은 첫 0.2초 집계와 종료 이벤트를 유지하되 이후 집계를 2초로 늘리고 화면에 각 부호별 최대 하나, 10px로 표시합니다. 보상과 보상 막대는 파란색으로 변경하고 막대 사이 간격을 3px에서 7px로 늘립니다. 학습 보상과 정책 차원·가중치·버전은 바꾸지 않습니다.

최대 이동은 관찰 표본에만 의존하지 않고 모든 완료된 학습 시도에서 `travelRecord`로 집계합니다. 출발점에서 가장 멀리 간 앞뒤 거리의 절댓값을 비교하고 새로운 최고 기록에서만 파란 깃발의 세계 좌표를 갱신합니다. 과제·지형 변경과 재접속에도 모델과 함께 유지됩니다. 이전 모델의 가중치·횟수·그래프는 유지하며, 과거에 저장하지 않았던 최대 이동 좌표는 복원하지 않습니다. 화면에서 별도 실행하는 모델이나 검증만으로는 학습 기록 깃발을 갱신하지 않습니다.
