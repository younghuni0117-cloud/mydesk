# Supabase 자동 동기화

`mydesk-robot-sync` 프로젝트를 서울(`ap-northeast-2`)에 생성하고 연결했습니다. 생성 시 확인된 비용은 월 $0(무료 플랜)입니다. 기존 `My_Desk` Supabase 프로젝트와 GitHub Pages 주소는 유지합니다.

- 대시보드: https://supabase.com/dashboard/project/htqqcttxeabicqvmphlb
- 홈페이지: https://younghuni0117-cloud.github.io/mydesk/robot.html
- API: https://htqqcttxeabicqvmphlb.supabase.co
- 마이그레이션: `create_private_robot_models` (`schema.sql`)

## 사용하기

로봇 페이지의 저장 상태 또는 도움말·모델을 열고 PC와 모바일에서 **같은 이메일**로 로그인합니다. 이메일 로그인 링크는 로그인할 기기의 브라우저에서 여세요. 최초 로그인 후에는 토큰을 브라우저에 보관하고 갱신합니다. 학습은 각 기기의 CPU에서 하고 서버는 공통 모델·시도 횟수·학습 분포·검증 기록을 저장합니다.

변경 모델은 10초 지연 저장하고 15초마다 서버 상태를 확인합니다. 계속 학습 중이어도 주기 확인에서 업로드를 시도합니다. 학습 종료 시에도 즉시 저장을 시도합니다. 상태가 ‘동기화 완료’가 된 뒤 다른 기기에서 이어 사용하세요. 창이 닫히기 직전의 전송은 보장하지 않으며 브라우저 저장을 지우면 아직 전송하지 않은 변경은 사라질 수 있습니다. 오프라인 데이터는 기기에 남기고 연결이 복구되면 재시도합니다.

이미 서버에 모델이 있으면 불러옵니다. 로그인 전에 학습한 로컬 모델이나 다른 기기에서 동시에 변경한 모델이 있으면 사용할 모델을 선택합니다. 파라미터를 평균내거나 횟수를 더해 가짜 통합 모델을 만들지 않습니다. 원본은 계정별 로컬 백업에 보관하며 선택 전에 모델 파일을 저장할 수 있습니다. 서로 다른 계정으로 전환할 때 모델과 진행 중인 요청을 분리합니다.

## 권한과 설정

`robot_models`는 인증된 사용자가 자신의 `user_id` 행만 조회·등록·수정하도록 RLS를 적용했습니다. 익명 접근은 거부합니다. 수정 시 `revision`이 예상 버전과 일치해야 하며, 다른 기기가 먼저 저장하면 선택 없이 덮어쓰지 않습니다.

`robot-sync-config.mjs`에는 공개 publishable 키만 포함합니다. service_role, secret 키, DB 비밀번호는 웹사이트나 저장소에 넣지 않습니다. Auth의 이메일 로그인을 활성화하고 Site URL과 허용 Redirect URL을 로봇 페이지로 설정했습니다. 이메일 발송은 Supabase 기본 서비스를 사용하며 수신 대상·발송량 제한이 있습니다. 조직 멤버가 아닌 이메일 사용자까지 확장하려면 별도 SMTP 설정이 필요할 수 있습니다.

## 검증

- 실제 서버: 트랜잭션 안의 두 테스트 사용자로 본인 행 조회·수정, 다른 사용자 읽기·수정·등록 차단, 오래된 revision 수정 차단을 검증하고 모두 롤백했습니다.
- 실제 HTTP: 공개 키로 이메일 로그인 설정·CORS를 확인하고, 익명 모델 조회 401과 인증 링크의 홈페이지 복귀(303)를 확인했습니다. 실제 이메일은 발송하지 않았습니다.
- Supabase 보안 검사: 지적 사항 없음.
- 클라이언트: `node --test tests/robot-sync.test.mjs tests/robot-ui.test.mjs` (실제 작업 스레드 조작 포함).

개인 이메일 수신·실제 두 기기 로그인은 해당 기기에서 확인해야 합니다. 로봇 움직임의 실제 Fold 브라우저 시각 검증은 별도입니다.
