# Mindmap shared library

The user-provided mobile export is the initial authoritative library. Personal map data and its connection credential are **not** shipped in the repository. The server row contains the library; browsers never upload pre-existing unrelated local libraries during their initial connection.

Devices connect once by opening a URL fragment carrying a cryptographically random 256-bit capability (`#mindmap=…`). The fragment is not sent to the static host or as an HTTP referrer. After a successful connection it is removed from the address bar and retained in this browser's separate connection storage. The “기기 연결” action explicitly shares/copies a connection URL for another device. Anyone possessing the link can read and edit this library; it must be treated as a credential. No password entry is required. A plain unconnected browser does not silently show its local content as shared data: it displays a connection dialog and disables editing until the initial authenticated read succeeds.

`public.mindmap_shared_library` uses RLS on both SELECT and UPDATE. Policies require a matching SHA-256 hash of the `x-mindmap-key` header. Uncredentialled and incorrect-key requests see no rows and cannot update data. Only the library column is writable by the API; the hash is not selectable. INSERT and DELETE are not granted. A server trigger increments the revision. No schema, grants, menus, permissions or data for other modules are modified.

Client writes compare the revision from which the edit was made. A stale write does not replace newer data. Its local draft is backed up before the latest server version is applied. Initial device content is also backed up before replacing it with the shared library; the very first pre-sync copy is preserved separately from the three recent conflict/reconnection snapshots. “기기 백업” downloads these copies. Original v1 storage is left intact. The regular “백업 저장” exports the current library.

Changes are automatically saved after editing. Other connected devices poll every three seconds while visible, deferring updates during text editing, dragging, context/rename menus and unsaved detail notes. Failed writes retain a pending snapshot with its original revision and are retried after connectivity returns. On reopening, a matching pending revision resumes; a stale one is backed up instead of uploaded. Details still use their existing explicit Save action. Current selection/view is kept local when applying remote changes; initial opening uses the shared active map.

Validation: six unit tests cover initial authority, two-device synchronization, conflict preservation, offline replay, stale pending replay and edit deferral. Two independent browser contexts verify initial local backup, text and notes synchronization, reconnect, fragment removal, unconnected gating and Fold outer/inner widths. Live API tests verify authorized access, unauthorized read/update rejection, hash column rejection, revision conflict rejection, and an identical-content authenticated save. Supabase security advisors reported no lints.

## Device connection clarification

Unconnected laptops still require the existing private capability once; this update does not make the library public or put a credential into the repository. The button explicitly copies the connection URL rather than opening an opaque native share sheet. Failed clipboard access exposes a selectable URL in the existing connection dialog. That dialog explains mobile copy → laptop open/paste. Hash changes in an already-open tab now initiate connection, including queued link changes during an ongoing connection. Connected devices retain their existing key, automatic polling and conflict/backup behavior. Data and RLS are unchanged. An authenticated metadata-only server inspection confirmed two maps are present, without reading or exposing map text or credentials.

Validation: connection URL round trip and foreign/invalid-link rejection plus existing synchronization/layout regression tests: 11 passed. Laptop connection completion still requires the owner to open/paste the mobile connection link; deployment alone cannot access a separate device's browser credentials.
